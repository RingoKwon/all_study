# Project 0 — js_profile

## I. 소개

자기 소개 프로필 페이지를 HTML과 CSS만으로 만든다.

**브릿지**: C에서 헤더 파일이 구조를 선언하고 소스 파일이 구현하듯, HTML이 문서 구조를 선언하고 CSS가 표현을 구현한다. 구조체 멤버가 계층을 이루듯 HTML 요소도 부모-자식 계층을 이룬다.

**신규 개념** (C에 대응 없음 — 여기에 시간을 쓴다):
- 시맨틱 HTML: 요소의 의미가 곧 구조. `<header>`, `<main>`, `<section>`, `<article>` 등
- CSS Box Model: content → padding → border → margin. 모든 요소가 이 박스 안에 산다
- Flexbox / Grid: 1차원/2차원 레이아웃. C에서 배열 인덱싱으로 위치를 잡는 것과 근본적으로 다른 선언적 배치
- 반응형 디자인: 뷰포트에 따라 레이아웃이 변하는 것. 고정 크기가 아닌 유동적 크기

## III. 필수 파트

프로필 페이지 1장. 아래 요구사항을 모두 충족한다.

### 기능 요구사항

1. **시맨틱 구조**: `<header>`, `<main>`, `<footer>` 최소 사용. `<div>` 남용 금지 — 의미 있는 요소가 있으면 그것을 쓴다.
2. **프로필 정보**: 이름, 사진(또는 플레이스홀더), 자기소개 텍스트, 기술 스택/관심사 목록, 연락처/링크.
3. **CSS 레이아웃**: Flexbox 또는 Grid를 사용한 레이아웃. 최소 한 섹션은 Grid, 한 섹션은 Flexbox를 사용할 것.
4. **반응형**: 데스크톱(1024px 이상)과 모바일(480px 이하) 두 브레이크포인트에서 레이아웃이 적절히 변한다.
5. **타이포그래피**: 본문과 제목의 폰트 구분. 일관된 크기 체계 (heading hierarchy).

### 시각적 체크포인트

구현 중 아래 시점에서 브라우저를 확인한다:

| # | 체크포인트 | 확인 사항 |
|---|-----------|-----------|
| 1 | HTML만 작성 후 | 브라우저에서 콘텐츠가 논리적 순서로 보이는가? CSS 없이도 읽을 수 있는가? |
| 2 | 기본 CSS 적용 후 | Box model 이해: padding, margin, border가 의도대로 작동하는가? |
| 3 | Flexbox/Grid 적용 후 | 레이아웃이 의도대로 배치되는가? |
| 4 | 반응형 적용 후 | 데스크톱 → 모바일 리사이즈 시 레이아웃이 깨지지 않는가? |

## V. 디펜스

### 예상 질문

**코드 워크스루:**
- HTML 문서의 전체 구조를 설명하라. 왜 이 요소를 여기에 썼는가?
- CSS 파일의 구성 원칙은? 선택자를 어떤 기준으로 작성했는가?

**개념 확인:**
- Box model의 네 영역을 설명하라. `width: 100px`에 `padding: 10px`을 주면 실제 너비는?
- `box-sizing: border-box`는 무엇을 바꾸는가?
- Flexbox와 Grid를 각각 어디에 썼는가? 왜 그 선택이 적절한가?
- 시맨틱 HTML이 왜 중요한가? `<div>`와 `<section>`의 차이는?
- `@media` 쿼리는 어떻게 동작하는가? 브레이크포인트를 어떤 기준으로 정했는가?
- CSS 우선순위(specificity)를 설명하라. inline > id > class > tag 순서를 아는가?

**라이브 수정:**
- 기존 레이아웃에 새 섹션을 추가하라 (예: "프로젝트 갤러리")
- 특정 브레이크포인트에서 레이아웃 변경 요청 (예: 3열 → 2열)
