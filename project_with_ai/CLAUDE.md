# project_with_ai

`AllStudy/CLAUDE.md`의 원칙을 상속한다. 이 파일은 프로젝트 실행 시스템의 규칙을 정의한다.

---

## 학습 방향

프로젝트 완성은 table stakes다. 진짜 가치는 **프로젝트에서 뽑아낸 이해가 다음 프로젝트에서 복리로 작동하는 것**이다.

- **Production speed** (프로젝트를 끝내는 속도)는 AI가 평준화한다. 여기서 차별화는 없다.
- **Learning speed** (가설→구현→이해 사이클의 질)이 6개월 후 역량 격차를 만든다.
- 같은 프로젝트를 끝내더라도, 추출한 패턴이 다음 프로젝트의 브릿지가 되는지가 복리의 조건이다.

실행 원칙:
1. 프로젝트를 끝낸 후 "이 프로젝트에서 다음에 재사용할 패턴이 뭔가"를 디펜스에서 반드시 짚는다.
2. 빨리 끝내는 것보다 **설명할 수 있는 상태로 끝내는 것**이 우선이다.
3. AI가 생성한 코드를 그대로 쓰되 설명 못하면 — 그건 학습이 아니라 production이다. 멈추고 이해한다.

## 프로젝트 라이프사이클

### 1. SUBJECT.md 작성

프로젝트 시작 전 Claude가 스펙을 작성한다. 이전 프로젝트가 done이 아니면 다음 SUBJECT.md를 작성하지 않는다.

SUBJECT.md 구조:
- **I. 소개** — 프로젝트 목적, 브릿지(기존 지식 연결), 신규 개념
- **II. 공통 지침** — 제약 조건 (금지 사항, 환경 요구사항)
- **III. 필수 파트** — 기능 요구사항 + 시각적 체크포인트
- **IV. 보너스** — 필수 파트가 완벽할 때만 시도
- **V. 디펜스** — 예상 질문 목록 (코드 워크스루 + 개념 확인)
- **Defense Log** — 디펜스 결과 기록 (스펙과 결과가 한 파일에)

### 2. 구현

`assignment/` 디렉토리에서 작업한다.

구현 규칙:
- 브라우저 피드백 루프를 최대한 활용한다. 한 기능 → 즉시 브라우저 확인 → 다음 기능.
- 설계에 오래 머물지 않는다. 3회 이상 설계 논의가 이어지면 "일단 짜봐" 트리거.
- SUBJECT.md의 시각적 체크포인트를 기준으로 진행도를 확인한다.

### 3. 디펜스

구현 완료 후 Claude가 peer evaluator로 디펜스를 진행한다.

---

## 디펜스 프로토콜

### 단계

| 단계 | 내용 | 시간 |
|------|------|------|
| 1. 코드 워크스루 | 링고가 코드를 처음부터 끝까지 설명 | 자유 |
| 2. 개념 확인 | SUBJECT.md의 디펜스 질문 + 즉석 질문 | 질문당 2분 |
| 3. 라이브 수정 | Claude가 요구사항 변경을 제시, 링고가 즉석 수정 | 10분 |
| 4. 판정 | PASS / RETRY | - |

### 판정 기준

**PASS 조건 (모두 충족):**
- 필수 파트 전체 동작
- 코드 워크스루에서 모든 라인의 의도를 설명
- 개념 확인 질문 80% 이상 정답
- 라이브 수정 완료

**RETRY:**
- 위 조건 미충족 시. 부족한 영역 명시 후 재도전.

### Defense Log 형식

디펜스 결과는 SUBJECT.md 하단 Defense Log 섹션에 기록:

```
### Defense Log

| 회차 | 날짜 | 결과 | 비고 |
|------|------|------|------|
| 1 | YYYY-MM-DD | PASS/RETRY | 부족한 영역 또는 특기사항 |
```
